# Revisão 2 · decisões alteradas em 19/11/2026

| Tema | Direção anterior | Decisão aplicada nesta revisão | Efeito verificável |
|---|---|---|---|
| Estratégia | Descoberta e confronto competitivo abriam o cronograma | Construção desktop desde a primeira semana | Primeiro item é um executável Tauri que lê Git real |
| Produto | Retomada de uma tarefa ancorada em commit | Inteligência de projetos, operações, contexto/evidências e extensibilidade | Três jornadas atravessam chat, sessão, Git e revisão |
| Valor diário | Tempo de retomada como principal medida do produto | Dias com um ciclo de projeto inspecionado; tempo de retomada vira uma medida específica | Uma consulta com fonte, uma alteração revisada ou uma decisão podem constituir um ciclo útil |
| Desktop e CLI | CLI era produto inicial; desktop dependia de prova comparativa | Desktop é a superfície principal; CLI é ferramenta complementar futura | Home, sidebar e visão do projeto entram na S1 |
| Concorrentes | Sobreposição podia encerrar ou redirecionar a tese | Manter pesquisa e incorporar os padrões que ajudam o usuário | Matriz aponta decisões de composição e reuso responsável |
| Git | Snapshot limitado a commit | Separar commit, índice/disco, contexto de execução e evidência | Um teste sobre staged e uma edição unstaged permanecem distinguíveis |
| IA | Codex recebia principalmente pacote para revisão em leitura | Codex responde no chat e realiza tarefa supervisionada em ambiente autorizado | S2 exige chamada real, S3 exige tarefa e prévia de mudança |
| UX | Caderno de revisão como interface global | Bancada multiprojeto com inspetor contextual | Nove superfícies projetadas, Home e revisão ilustradas e protótipo navegável |
| Arquitetura | Serviço centrado no compilador de passagem | Núcleo de projetos, sessões, eventos, operações e dados com IDs comuns | Mesmo evento atualiza histórico, atividade e estado da tarefa |
| Início da execução | Entrevistas, metas de amostra e contrato congelado | Interfaces pequenas versionadas durante implementação | D01–D07 têm ordem, horas, testes, DoD e prompt pronto |
| Pesquisa e carreira | Validação quantitativa condicionava novos investimentos | Pesquisa aprofundada após implementação funcional | Instrumentação e corpus aproveitam o que já foi construído |
| Distribuição | Adoção e comercialização misturadas à decisão inicial | Windows e PT-BR primeiro; comunidade e serviços acompanham releases | MVP útil sem conta própria; adoção é observada sem projeções artificiais |

O que foi preservado: levantamento competitivo, fontes primárias, pesquisa acadêmica, disciplina de comparação, proveniência, recuperação de falhas, revisão humana, proteção de credenciais e distinção entre resultado observado e inferência.
